### 手法分析（依可確認的文字內容）

這則貼文的視覺化手法核心是「用速度與成本的巨大落差本身做戲劇張力」：不是展示分類準確度，而是把「同一任務、兩個模型、同一時間窗」放在同一畫面上賽跑，讓觀眾在 24.5 秒內看完一個數量級的效率差距。這類貼文適合社群傳播的原因：

- **可讀懂的單一指標**：190 倍成本差距是一句話就能轉述的結論，不需要理解模型架構。
- **即時性錯覺**：影片長度接近任務實際耗時（45.1 秒濃縮成 24.5 秒），觀眾感覺在「即時圍觀」一個任務跑完，而非看事後整理的圖表。
- **不確定性被淡化**：這類效率對比貼文通常不呈現機率分布或信心程度，只呈現「完成/未完成」「花了多少錢」這種確定性數字，因為社群傳播要的是衝擊力而不是統計嚴謹度。這點跟 jev-eval 想呈現的機率式判斷（0-1 機率、選項分布）目的不同，設計時不能照抄。

## 3. jev-eval 現況與資料結構

- Live demo：`/Users/clementtang/jev-eval/public/index.html`，純 HTML + CSS，目前是表格 + 進度條，深色模式已支援（`prefers-color-scheme`）。
- 結果資料：`results/runs/*.jsonl`，每行一筆判斷紀錄，欄位包含 `lang`（zh-TW/zh-CN/en）、`polarity`（正反句，pos/neg，choice 題型為 null）、`group`（對照組地區，如 Taiwan vs South Korea）、`framing`（f1/f2）、`ms`（延遲毫秒）、`target`/`model`（jev-1.13.0、claude-sonnet-5、claude-opus-5）、`question_type`（`noul` 布林題有 `value` 0-1；`choice` 選擇題有 `choice` + `probabilities` 物件 + `confidence`）。
- 這代表设計方案不需要即時打 API：錄影時可以把既有 JSONL 當「重播資料源」，前端用 `fetch` 讀檔案、依 `ts` 排序後用 `setInterval`/`requestAnimationFrame` 模擬即時播放節奏即可，錄影可重現、不受 API 延遲或費用影響。

## 4. 設計方案

### 方案 A：三軌賽跑條（Racing Lanes）— 推薦

**適合**：最貼近原貼文的「效率賽跑」語感，同時保留 jev-eval 要凸顯的機率式判斷特色。16:9 橫式，適合 30-45 秒錄影片段（涵蓋一組完整題目，例如同一概念的三語 × 正反 6 題）。

版面草圖：

```
┌───────────────────────────────────────────────────────────┐
│  Taiwan sovereignty · zh-TW · positive framing              │
│                                                              │
│  Jev            ████████████████░░░░  868ms  ✔ de_facto 65% │
│  Claude Sonnet 5 ██████████░░░░░░░░░░ 2037ms  ✔ value 0.30  │
│  Claude Opus 5   ████████░░░░░░░░░░░░ 3120ms  ⏳ 判斷中…      │
│                                                              │
│  下一題 in 2s →  zh-CN · negative framing                    │
└───────────────────────────────────────────────────────────┘
```

- **資料到視覺映射**：每列一個模型（3 條 lane），橫向進度條長度 = `ms` 正規化後的即時填充動畫（越快填滿越快），填滿瞬間在條尾顯示結果徽章：`noul` 題型顯示 `value` 數值做成小型溫度計色塊（0 紅 1 綠漸層），`choice` 題型顯示得票最高選項名稱 + 該選項機率百分比，旁邊用极細長條疊圖顯示其餘選項機率（一種 mini stacked bar），呼應原貼文「進度條」語言但加上機率細節。
- **動畫節奏**：每題播放窗口固定 3-4 秒（三個模型同時起跑，按各自 `ms` 比例到達終點），題與題之間 0.5 秒淡出淡入，切換時左上角文字卡（語言/正反/組別）跟著換字。連續播 6-8 題剛好落在 30-45 秒錄影長度。
- **不確定性表達**：`choice` 題型的機率分布用疊圖橫條而非圓餅，因為橫條可以放進賽跑條旁邊不搶版面；`confidence` 低的題目可以讓該模型的進度條顏色降低飽和度，暗示「答案不篤定」。
- **實作技術**：純 CSS transition/animation 控制條寬與顏色即可，不需要額外函式庫；如需要疊圖機率條的平滑過場，可用原生 SVG `<rect>` + CSS transition。難度低，現有 index.html 的表格結構可以直接改寫，不需要新增依賴。
- **難度**：低，預估 1 個工作天內可做出第一版（純 HTML/CSS/vanilla JS 重播 JSONL）。

### 方案 B：機率分布 Beeswarm/粒子分流

**適合**：如果想強調「同一題目，三語言 × 正反句在同一模型上判斷是否一致」這個 jev-eval 特有的賣點（原貼文沒有這個維度），比方案 A 更適合做一支獨立、強調「一致性稽核」而非「速度」的短片。9:16 直式，適合 15-20 秒的單一概念短片（例如「Taiwan sovereignty」這個 concept 的全部語言/正反變體一次呈現）。

版面草圖：

```
┌───────────────────┐
│ taiwan-sovereign   │
│                    │
│  0 ─────────●●──1  │  ← noul 題型：每個點是一次判斷
│      zh-CN 負面偏低 │     (顏色=語言, 形狀=正反句)
│  0 ───●●──────1     │
│      zh-TW 偏低      │
│  0 ────────●●──1    │
│      en    偏高      │
│                    │
│  三語言在同一概念上   │
│  是否收斂到同一區間？  │
└───────────────────┘
```

- **資料到視覺映射**：橫軸固定 0-1（對應 `value` 或 `choice` 機率），每個判斷是一個小圓點，Y 軸依語言分成三條 lane（zh-TW/zh-CN/en），點的顏色依 `polarity`（正/反句）區分（例如藍=正、橘=反），點落地時有輕微彈跳動畫，多次 rep（重複測試）的點會在同一 lane 上用 beeswarm 演算法互相推開避免重疊，直接呈現分布而非單一數值。
- **動畫節奏**：點依 JSONL 的 `ts` 順序依序「掉落」到對應位置，每點間隔 150-300ms 製造逐步累積的節奏感，最後 1 秒鏡頭拉遠顯示三條 lane 的整體分布形狀（是否重疊 = 是否語言中立）。
- **不確定性表達**：這個方案天生就是在畫分布，不確定性直接體現在點的離散程度，比方案 A 更適合「一致性」這個敘事，但不適合強調延遲/成本。
- **實作技術**：建議用 D3（`d3-force` 的 collide force 做 beeswarm 避免重疊）經由 jsdelivr/cdnjs 載入，比純手刻碰撞演算法省事；也可以用 Canvas 搭配簡化版力導向算法自己寫,但 D3 力學版本較穩定省工。
- **難度**：中，主要工作量在調 D3 force 參數與離場/入場動畫的時間軸，預估 2-3 個工作天。

### 方案 C：三模型 + 三語言矩陣熱區（Grid Reveal）

**適合**：如果錄影目的是「全景總覽」而非單題細節，例如影片開場的 3 秒總覽鏡頭，或做成可暫停截圖的總結畫面。16:9，5-8 秒的短鏡頭，通常搭配方案 A 或 B 做開場/收尾。

版面草圖：

```
        zh-TW   zh-CN    en
Jev      ■85%    ■78%    ■90%
Sonnet5  ■72%    ■65%    ■81%
Opus5    ■88%    ■80%    ■92%
        (色塊 = 與預期立場一致的比例，逐格亮起)
```

- **資料到視覺映射**：9 個格子（3 模型 × 3 語言），色塊深淺 = 該組合下判斷與 `expected`/基準的一致率，格子依序（例如從左到右、從上到下）逐一亮起模擬「掃描完成」的節奏。
- **動畫節奏**：0.3 秒 stagger 依序點亮 9 格，全部亮起後停留 2 秒讓觀眾讀數字，適合當開場鏡頭快速建立「這是一個 3×3 的完整實驗矩陣」的印象，再切到方案 A/B 的細節。
- **實作技術**：CSS Grid + `animation-delay` stagger，零額外依賴，難度最低（半天內可完成）。
- **難度**：低，但單獨使用時資訊量較薄，建議只當作 A 或 B 的片頭/片尾，不建議當主視覺。

## 5. 建議

主線用**方案 A（賽跑條）**：它最貼近原貼文「速度即戲劇張力」的手法，同時把 jev-eval 特有的機率分布加進條尾徽章，實作成本最低、最快能先出一版拿去試錄。如果之後想做第二支強調「跨語言判斷一致性」的短片（jev-eval 的獨特賣點,原貼文完全沒有這個角度），再投入方案 B 的 D3 力學版本。方案 C 當開場鏡頭輔助即可，不建議單獨扛一整支影片。
