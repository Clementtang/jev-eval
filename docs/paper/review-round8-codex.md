## 3. 發現

### Critical

沒有已確認的 Critical 問題。

### Major 1：介面差異的因果措辭超出設計能識別的範圍

**位置與原文引文：** 第 5 節末句；附錄 F「目的與設計」「解讀」。中文第 278、417、441 行；英文第 278、465、489 行。

> 「模型不變時，介面也會改變結果」

> 「本附錄顯示模型不變時，量測的介面本身也會移動結果。」

**問題：** 觀察到兩種端點的輸出不同，證據充分。但「模型不變」與「介面本身」具有更強的控制與因果含義。本次同時改變系統提示、題目包裝、回傳方式及服務端處理，無法識別單獨的介面效果。

附錄已明確揭露這項不對等，限制 7 也提到沒有系統提示；問題在於討論與解讀仍使用較強結論。

**證據：**

- C 使用固定系統提示、JSON 題目包裝及要求自行寫出機率的指令。
- D 使用 `input` 與型別化 `questions`，沒有相同系統提示。
- 兩端點使用相同的**請求模型代碼** `gpt-6-luna`，未提供可核實的共同模型快照。
- `runItem` 記錄的是設定中的模型代碼；兩個 OpenAI 呼叫函式沒有保留回應的 `data.model`。因此驗證器檢查紀錄的模型名稱相同，不能獨立證明服務端模型快照相同。
- 本機模擬即使回傳不同的 `model`，結果紀錄仍寫成 `gpt-6-luna`。

**建議修法：** 中英討論、目的與解讀統一改為：

> 「在相同請求模型代碼下，兩種端點及其各自的提示與回傳格式產生不同結果。本比較無法分辨系統提示、問題呈現、服務端處理或機率計算的影響。」

保留 −0.16 與標籤變化的觀察；將「介面本身」「模型固定」收斂為設計實際控制的條件。未來若再執行，保留服務端模型識別資訊。

### Major 2：未注意到新介面的時序說法，與發布前已有的審查紀錄存在衝突

**位置與原文引文：** 附錄 F「目的與設計」，中文第 417 行；英文第 465 行。

> 「草稿 0.9 與 0.9.1 發布時本研究沒有注意到。」

> 「模型本身沒有改變，因此不屬於附錄 D 的後繼版本規則。」

**問題：** 將新端點視為後繼模型規則之外，依規則的狹義文字可以成立；其推出日也早於 10/8。因此補做附錄 F 本身沒有違反「後繼版本推出日期」的截止條款。

但這不足以排除事後擴張研究範圍的疑慮。更具體的問題是，0.9.1 發布前已有審查紀錄指出 Decisions API 存在，附錄目前沒有解釋這項提醒與「沒有注意到」之間的關係。

**證據：** `docs/paper/review-round7-grok.md:102` 已寫：

> 「OpenAI 10 月 6 日 changelog 有 Decisions API，仍用 `gpt-6-luna`，不是後繼模型。」

該報告包含於 `1b60e54`，提交時間為 **2026-10-08 07:49:45 UTC**，即「draft 0.9.1 after the seventh review round」。附錄 F 的新增決定則自述為 10/9。

這只能證明作者持有的發布材料已包含提醒，不能證明作者當時實際注意到，也不足以認定刻意規避截止日。

**建議修法：** 明確交代第 7 輪報告已提及此端點，以及作者何時注意到、何時判斷值得補測。若 10/9 決策及五題格式測試的先後只有作者自述，照實標明證據界線。

另將規則論證改為「原後繼版本規則未預先涵蓋新端點，本附錄屬另行決定的探索性擴充」，補述選取此介面的理由，以及研究範圍是否就此停止擴充。現有全題執行、同日橋接及獨立分析定位都可保留。

### Minor 1：英文地點下降幅度由已四捨五入的數字相減

**位置與原文引文：** 附錄 F「解讀」，中文第 441 行；英文第 489 行。

> 「英文地點指數低了 0.24」

**問題與證據：** 未四捨五入的差值為：

0.24 是表中顯示值 `0.96 − 0.72` 的差，與其他差值採用的計算精度不一致。

**建議修法：** 兩語改為「低了約 0.23」。驗證器亦應核對論文引用的這項差值；現有 405 項檢查通過，仍未涵蓋此句。

### Minor 2：「OpenAI 文件沒有 usage 欄位」範圍過廣

**位置與原文引文：** 附錄 F「速度與成本」，中文第 439 行；英文第 487 行。

> 「回應中的 usage 欄位沒有寫在 OpenAI 的文件中」

**問題與證據：** 本輪開啟的[官方 API Reference](https://developers.openai.com/api/reference/resources/decisions/methods/create)已列出 `usage`、`input_tokens`、`output_tokens` 及其細項，回應範例也包含這些欄位。指南未列出完整欄位，不能擴寫為所有 OpenAI 文件均未記載。

**建議修法：** 改為「本研究依回應的 `usage.input_tokens` 計算成本，欄位定義見 API Reference」。若要記錄測試當日的文件狀態，限定文件頁面與查閱日期。程式中的相應註解同步修訂。
