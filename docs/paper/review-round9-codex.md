## 1. 總評（先揭露你所屬廠商與受測模型的關係）

我是 OpenAI 的 Codex 審查者，與受測的 GPT-6 Luna、GPT-6 Sol，以及附錄 F 的 Decisions API 同屬 OpenAI，具有廠商利益衝突。

**本輪新增引用大致準確、公允，但建議發布前修正兩項 Major 與一項 Minor。沒有 Critical 問題。** 主要問題是新增文獻後的貢獻措辭，以及時間線對 Git 證據的表述。

已成功核對 [Hsiao repo 的公開 README](https://github.com/pirrer/taiwan-sovereignty-decision-models#readme)。作者察覺研究的時間、授權中止原因與分析腳本寫成時間，依本輪提供的工作紀錄及作者陳述判斷，未獨立查證原件。全程唯讀，沒有修改、建立或刪除檔案，也沒有呼叫模型 API。版本號不在本輪審查範圍。

## 2. 發現

### Critical

沒有。

### Major 1：新增 Hsiao 後，四項「延伸」的指涉產生誤導

**位置與原文引文：** [中文版第 42 行](paper.zh-TW.md)、[英文版第 42 行](paper.en.md)。

> 「本研究在四個面向延伸這些研究：測試結構化判斷模型……」

> “We extend this work in four ways: we test a structured decision model…”

**問題：** Hsiao 已被加入「這些研究」的範圍，但它本身就測試四個結構化判斷模型。英文的 “this work” 又緊接 Hsiao 的描述，容易被理解為本文延伸 Hsiao，與主要研究先公開的時間線形成不必要的混淆。這涉及貢獻定位與來源歸屬，超過一般文字潤飾。

**證據：** Hsiao 的 README 明確列出四個判斷模型，研究也包含措辭與角色條件。因此「測試結構化判斷模型」無法作為本文相對於該研究的新增面向。[來源](https://github.com/pirrer/taiwan-sovereignty-decision-models#readme)

**建議修法：** 將原四項延伸明確限定於前述較早的文獻，再另段介紹 Hsiao；或改寫為：

> 「本研究與 Hsiao（2026）都評測結構化判斷模型。本文另外將主張、強迫選擇與實務標籤並列，檢視不同量測工具是否改變模型排序；附錄 F 則比較同一請求模型代碼的兩種端點。」

保留客觀公開日期即可，避免讓「延伸」同時承擔貢獻與時間先後的含義。中英同步修訂。

### Major 2：時間線混用了執行程式、分析程式與提交時間

**位置與原文引文：** [中文版第 417 行](paper.zh-TW.md)、[英文版第 467 行](paper.en.md)。

> 「指令與程式沒有再修改」

> 「分析程式 `scripts/appendix-f.mjs` 寫於批次開始之後」

> 「git 紀錄只能證明附錄的文稿與程式寫在批次之後。」

英文也使用 “the command and code were not changed afterwards” 與 “were written after the batch”。

**問題：** 「程式沒有再修改」需要限定檔案與期間，否則容易涵蓋後來才建立的分析程式。更明確的錯誤是將 Git 的提交時間寫成檔案的寫成時間。原有最後一句與本輪新增時間線合讀，會把批次執行中的分析工作誤寫成批次結束後才開始。

**證據：**

- 本輪背景只支持首次中止後至重新執行前沒有修改檔案。
- 分析脚本據工作紀錄在 10 月 10 日 **12:18 UTC** 寫成。
- 本輪直接讀取原始紀錄，批次最早回應為 **12:17:02.031 UTC**，最後回應為 **12:37:02.831 UTC**。12:18 位於批次執行期間。
- `appendix-f.mjs` 首次納入 Git 的提交為 `ebcf304`，晚於批次；這只能核對提交時間，無法證明檔案首次寫成時間。

**建議修法：** 明確分開三件事，例如：

> 「依工作紀錄，10 月 9 日首次啟動中止後，至 10 月 10 日重新啟動前，批次指令及所用執行程式未變更。依作者陳述，作者於 10 月 10 日上午（河內時間，UTC+7）看到貼文並得知該研究。12:16 UTC 重新發出相同指令，原始回應紀錄涵蓋 12:17 至 12:37 UTC；分析程式於 12:18 UTC、批次仍在執行時寫成。Git 紀錄顯示包含文稿與程式的提交晚於批次，無法證明首次寫成時間。」

這樣足以交代執行條件延續的證據，同時保留讀者判斷後續分析與解讀是否受影響的空間。

### Minor 1：「方向一致」應明確指出比較軸

**位置與原文引文：** [中文版第 441 行](paper.zh-TW.md)、[英文版第 491 行](paper.en.md)。

> 「……與本附錄方向一致。兩者比較的對象不同：該研究比較同一端點下的不同字形，本附錄比較同一語言下的不同端點。」

**問題：** 已揭露題目、指數與比較對象不同，也沒有直接比較差距大小，這些界線正確。但「方向一致」緊接附錄的端點差異結論，仍讓讀者需要猜測所指的比較軸。兩種對照無法直接構成同一效應的再現。

**證據：** 表 F1 本身提供更直接的描述性對照：Decisions API 的地位指數繁中為 0.83、簡中為 0.66，確實也是繁中高於簡中。可用這個端點內的字形比較支持該句，無須借用端點間差異。

**建議修法：**

> 「Hsiao（2026）與本附錄表 F1 都觀察到，同一 Decisions API 端點的繁體版本指數高於簡體版本。兩研究的題目、提示與指數定義不同，此處只比較描述性方向，不比較數值或差距大小。」

若保留其數字，補明 Index S 的 +1 代表與台灣自主治理一致。

## 3. 不需修改但值得記錄的觀察

1. **「四個判斷模型」忠於原文。** Decisions API、Jev、Clef、Clef-flash 為四個判斷模型；Haiku 5.5 為生成式對照模型。將後者排除在「四個」之外，沒有貶低或漏算。本文引用的 0.85、0.68 與 README 相符，題庫改寫及繁簡逐字轉換的描述也正確。「較偏向」保留了相對差異的意思，沒有把仍為正值的簡體指數說成整體支持中國立場。[來源](https://github.com/pirrer/taiwan-sovereignty-decision-models#readme)

2. **兩個關鍵時間差已有揭露。** 貼文比決定早 12 分鐘，正文直接寫出；repo 公開至作者詢問相隔 **14 小時 22 分鐘**，現有日期與時間可算出。作者得知研究後才重新執行，也有寫明。建議把這一整段統一標示為 UTC，河內上午另註 UTC+7。

3. **現有文字沒有直接宣稱「設計不受 Hsiao 影響」。** 「設計沒有因此調整」的「因此」指五題格式確認。沿用指令能支持執行條件延續，無法證明後續分析、解讀或呈現完全不受影響。本輪證據也不足以認定作者受到影響。

4. **公開先後可以保留，無須推導優先權。** 主要草稿先公開、Hsiao 在附錄 F 批次前公開，兩件事可同時成立。「獨立公開」宜限於另一項研究自行發布的意思，避免擴寫為已證實彼此沒有接觸或影響。第 2 節的主要問題已列於 Major 1。

5. **摘要、第 7 節與限制沒有必須補上 Hsiao 引用的缺漏。** 摘要報告本文結果；第 7 節處理工具、廠商與財務關係；限制已有題庫、尺度及黑箱界線。第 2 節與附錄 F 已提供引用。第 5 節「語言」段加引 Hsiao 有助於讀者連結最接近的文獻，但現況不足以判定為實質漏引。

6. **本輪新增文字中英大致同義，繁中用語適當。** 「中國」在本文已定義為中華人民共和國，與英文 PRC 對應；「繁體字」「簡體字」「題庫」「端點」均適合台灣用語。上述問題兩版共有，未見只在某一版強化優先權或弱化外部研究的情形。
